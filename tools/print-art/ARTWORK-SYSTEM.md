# Actual-dog preparation contract

This is the E2 preparation foundation, governed by `docs/history/CREATIVE-AND-UX-2026-10-24.md` (moved there from docs/continuation on 27 Oct) and the current scope in `docs/SCOPE.md`. Its browser bundle is local; its native candidate adapter has been applied to isolated Teeinblue drafts. It does not generate, upload, retry or purchase anything. See `docs/evidence/2026-10-24-six-style-integration.md` for current verification and limits.

`recipes-v1.json` defines the six candidate media, shared three-stop tone and five distinct format compositions. Framed and unframed portraits share the portrait scene. The approved screenprint portrait and word-free blanket remain the visual anchors. These recipes have not passed a new image evaluation; distinct instructions do not establish distinct acceptable outputs.

`artwork-system.mjs` consumes the current `HSArtworkProfile` facts schema instead of creating a competing personality extractor. It requires original-photo and sanitized-upload hashes, explicit city provenance, exact copy ownership, model, variant and recipe/layout versions. It compiles a deterministic request key and returns exact text separately from the word-free image prompt. A boolean attestation of metadata removal is not proof that stripping occurred; the eventual upload adapter must establish it from actual bytes.

The local request-state functions demonstrate the integration contract: selecting a tone makes no request, manual words are preserved with a rewrite offer, one deliberate action starts a pending request, an uncertain outcome survives serialization/reload, and another request is blocked until that outcome is reconciled. Receipts must match the complete input key, carry original dimensions and identify the output bytes. A stale response stays in evidence and cannot become the current preview unless the buyer returns to that exact input version. Switching among completed input versions reuses their receipts without another request. The last displayable preview remains separately available while choices are stale. `lastGood` means a structurally valid returned image, not accepted likeness or print quality. Purchase always remains disabled in this preparatory module.
