## How to use this checklist

- Each ID is one work item. Unticked is not complete. Prefixes: NOT RUN, PARTIAL, BLOCKED, APPROVAL, DEFERRED. Mark PASS only with a dated evidence link, revision/target and observed result. A documented gate is not a passed gate.
- Work top to bottom within each stage. External blockers block their dependants, not independent work. E1 cost/supplier reads and no-cost E2/E3 preparation may advance while support is pending.
- Product designs and integration precede E5 website mockups. E6 physical samples are last in testing. E7 upgraded live release waits for samples to pass.
- Record per-output/variant findings in the existing acceptance evidence; do not create another task queue. When a checkpoint completes, update NOW.md with one next action.
- Use the smallest evidence-producing step. Re-run passed tests only after relevant changes, failures or new uncertainty.
- If a task becomes unnecessary, record NOT APPLICABLE with the reason and owner decision where scope changes. Do not silently delete a failed style or core product.

## Gate definitions

**Ready to review styles:** actual six outputs plus source comparisons, receipts and costs, with remaining uncertainty visible.

**Ready to place mock/sample order:** applicable E1-E5 results accepted, exact final art/variant basket and route proved, itemized payable quote prepared, recipient confirmed privately, manual holds understood. E6-08 still requires payment approval.

**Ready to launch:** physical samples accepted, current art/site/runtime and pricing/operational gates satisfied, exact release package prepared. E7-12 still requires launch approval.

**Launched and verified:** approved main revision/native configuration/catalog is live, intended items alone orderable, downstream source/fulfillment state checked and measurement works. This is distinct from being ready.
